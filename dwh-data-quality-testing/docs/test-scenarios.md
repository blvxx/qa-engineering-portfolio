# DWH test scenarios

| ID | Flow | Scenario | Expected result | Type |
|---|---|---|---|---|
| DWH-01 | Raw → Staging | Load clean source batch | Every source row appears in staging | Positive |
| DWH-02 | Staging | Duplicate invoice ID | DQ-002 fails; core promotion is blocked | Negative |
| DWH-03 | Staging | Missing customer or invoice ID | Required-field rule fails | Negative |
| DWH-04 | Staging | Zero/negative/invalid amount | Amount rule fails | Boundary / negative |
| DWH-05 | Staging | Unsupported currency/status | Domain rule fails | Negative |
| DWH-06 | Staging → Core | Replay same batch | One core row per invoice ID; values stay stable | Idempotency |
| DWH-07 | Core → Mart | Rebuild aggregate twice | Counts and totals stay unchanged | Idempotency |
| DWH-08 | Raw → Staging | Source/staging count mismatch | DQ-001 fails | Reconciliation |
| DWH-09 | Core → Mart | Change a mart aggregate | DQ-007 fails | Reconciliation |
| DWH-10 | Airflow | Fail a task and retry | Retry visible; downstream tasks wait | Recovery |
| DWH-11 | Airflow | Clear and rerun a task | Same batch ID is reused for the same DAG run | Replay |
| DWH-12 | Airflow | Provide date boundaries | Only rows in the inclusive period are ingested | Date-slice replay |
| DWH-13 | Access | Query another tenant | Denied by tenant-aware service/data layer | Design-only; not implemented in this single-tenant lab |

The committed CSV is a clean synthetic baseline. Negative DQ cases are generated by unit-test fixtures so the default pipeline can complete successfully.
